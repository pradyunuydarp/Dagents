\section{The two rule tables}
\label{app:rules}

\Cref{tab:rules} sets the strategies of GRAILS (its Table~1) beside those of the
Dagents governance planner. GRAILS lists one or more transformations for each
case; Dagents chooses exactly one strategy. GRAILS's ``moderate'' sensitivity
corresponds to Dagents's ``medium''. The model-update column exists only in
Dagents. Strategy names in Dagents: \emph{allow} returns the field unchanged;
\emph{gen} generalises it (level 1 rounds a number to the nearest 10);
\emph{redact} removes it; \emph{agg} returns only aggregates over at least the
minimum cohort; \emph{clip} bounds an update's norm to 1.0; \emph{noise} adds
Gaussian noise of scale 0.5 to an update; \emph{refuse} withholds it.

Three differences stand out. First, for high-sensitivity data and a low-trust
requester, GRAILS returns a masked or suppressed result, while Dagents refuses
the field at every granularity. Second, for column and table requests Dagents
returns only aggregates over at least the minimum cohort, where GRAILS uses
microaggregation or generalisation. Third, GRAILS adds noise to a low-sensitivity
cell for a low-trust requester, while Dagents returns it unchanged; Dagents
saves noise for model updates.
